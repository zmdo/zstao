# Harness 新项目自动接入与完整交付修正方案

- 日期：2026-11-10。
- 状态：实施中；完成情况与真实会话验收将记录在本目录。
- 延续：[项目构建与部署方案](../harness-project-delivery/README.md)。

## 1. 问题与目标

上一轮验收给 AI 提供了现成仓库地址、执行器和部署配置，证明已有项目可以构建部署，不能证明新会话能从自然需求自主创建项目。当前系统提示写死 OneDev SSH 地址，创建工具又从网页地址拼接 Git 地址；新项目不会自动匹配构建执行器，创建仓库成功但授权失败后重试也不能补齐。

本次目标：用户只提出应用功能和目标服务器，AI 通过系统提示、工具结果和交付 Skill 自主创建代码仓库、开发完整应用、检查并提交、构建镜像、部署和验收。无需在聊天中提供仓库地址、工具名称、执行器、镜像仓库或命令。

## 2. 最小实现范围

复用项目仓库插件、现有 OneDev 与 TCR 配置、`project-delivery` Skill 和现有构建 Agent。保持单项目、单环境、单应用服务器交付方式，不增加服务器或平台数据库表。

### 2.1 连接与默认值

现有项目设置增加一次配置的 Git SSH 根地址、托管项目空间、默认构建执行器和 Node 构建基础镜像。Git 地址默认可使用 OneDev 的 clone-url；内网访问不同于网页地址时显式配置 SSH 根地址，不推测端口。AI Git 身份与密钥继续使用平台已有身份。主机密钥文件由平台维护，工具只返回路径和连接参数，不返回密钥内容。

`create_project` 与 `get_project` 返回一致的 `git` 连接信息及 `delivery` 默认值。系统提示只描述行为与信息来源，不保存主机 IP。镜像仓库根据已配置 TCR namespace 与 OneDev 项目 ID 生成稳定名称，避免同名项目冲突；镜像管理 API 凭据和 Docker 推送/拉取凭据仍留在宿主与执行环境。

### 2.2 托管项目空间与创建恢复

使用 OneDev 父项目 `apps` 作为默认托管空间。`create_project` 接收项目短名称，创建 `apps/<slug>` 并返回完整项目路径。所有仓库/构建动作支持该完整路径。已有根项目仍可查询与交付，不迁移其仓库。

创建操作沿用宿主权限；同一托管项目重复调用时复用仓库，并核对/补齐 AI 写入权限。返回明确的 repository/access 就绪状态；任何步骤失败保留已创建的仓库，报告阶段和项目路径，重试继续补齐。对托管空间外的已有项目不自动更改授权，不在空间外创建项目。

### 2.3 构建与镜像准备

构建执行器一次配置为匹配 `apps/**` 下的 `build` Job，并保留两个已有项目的匹配。并发维持 1，新项目不需要逐个添加白名单。

在 `platform_onedev` 增加 `prepare_delivery`，针对已存在的托管项目检查执行器配置与在线 Agent，并准备该项目的私有 TCR 仓库。副作用沿用宿主授权。该动作返回可用的执行器、镜像地址、基础镜像及缺失项；不宣称凭据已通过实际推送验证，真实构建/拉取才是验收依据。重复调用先核对已有资源，创建响应不确定时复查，不盲目重建。

普通创建项目不必创建镜像仓库；用户要求构建部署时 Skill 调用 `prepare_delivery`。既有项目仍可使用已提交的交付配置。

### 2.4 Skill 与完整应用

Skill 覆盖新建并部署的入口，使用工具返回的 Git/构建信息生成项目配置；推送前使用 Git 完整 SHA，复用上一版固定镜像、冻结快照、后台发布、状态和回滚协议。

首次部署自行检查服务器已有端口和目录，选择独立应用目录/Compose 项目，准备仅含项目需要的环境文件；涉及用户尚未提供的业务密钥时明确缺项。示例升级为指导 AI 开发实际前后端应用，不把固定 JSON 响应当成完整项目。

## 3. 实施顺序

1. 编写本方案；核验 OneDev 16.9.7 项目层级、授权、执行器 API 与 TCR 个人版仓库创建 API。
2. 实现统一连接信息、托管项目创建恢复、嵌套路径和交付准备；补齐设置页面与 Skill。
3. 测试地址一致性、失败恢复、权限边界、资源复用、私有镜像仓库准备和已有项目兼容。
4. 线上配置 `apps` 与执行器范围，构建并发布 CES 新镜像，同步安装的 Skill；保留原镜像和配置用于恢复。
5. 创建全新标准 Harness 会话，只给业务需求及服务器名称，由 AI 自主实施。测试期间仅作用于新应用，保留已有服务。
6. 独立检查代码、构建产物、服务器状态、应用功能、持久化与会话恢复，记录真实工具调用和人工干预。

## 4. 验收需求与边界

新会话只输入类似以下的自然需求，不包含工具名称、仓库地址、镜像地址、执行器和操作命令：

> 创建一个完整的中文待办应用，部署到 B-163-98。需要浏览器界面、任务新增/编辑/删除、完成状态、优先级和截止日期、搜索筛选、统计，以及刷新和重启后数据保留。请完成开发、测试和部署，最后提供访问方式。使用独立的应用和空闲端口，保持已有服务运行。

完整验收包括：AI 主动使用 `create_project`；返回可用 Git 地址并成功提交；新项目自动匹配执行器；真实构建推送；按产物 digest 部署；前后端功能与持久化通过；重试不重复创建；新回合可查询已有记录继续工作。公网不可达时分别报告内部健康与外部访问，不据此声称用户已能公网访问。

会话若需要人工提供技术信息才能继续，则记录为入口缺口，修复平台/Skill 后再开全新会话复测。不能将人工补全提示后的成功标记为自然需求验收通过。

## 5. 接口核验依据

OneDev 使用当前部署版本 16.9.7 的 `ProjectResource`（parentId、clone-url、user-authorizations）、`UserAuthorizationResource`（createOrUpdate）与 `SettingResource` / `AgentResource`。源码核验与线上实际调用并行验证，不依据工具名称猜测接口。

TCR 使用官方的 [CreateRepositoryPersonal](https://cloud.tencent.com/document/api/1141/41597)，显式传入 `Public=0`；用 [DescribeRepositoryPersonal](https://cloud.tencent.com/document/api/1141/41582) 按准确名称核对仓库与私有属性。创建响应不确定时先查询；权限、配额或已有公开仓库冲突不被当作成功。
