# Agent 角色

一个 Agent 能做完，就不要拆。拆角色只在三种情况下值得：

1. **任务跨阶段**：既要调研、又要实现、又要独立验收。
2. **上下文超限**：一个对话塞不下全部材料，需要分工持有。
3. **需要交叉验证**：结论重要到必须由另一个视角复核。

## 交接协议

角色之间只传递四样东西，缺一样就不算完成交接：

| 字段 | 内容 |
| --- | --- |
| 结论 | 一句话说清做到哪、结论是什么 |
| 证据 | 文件路径与行号、命令输出、测试结果 |
| 未决问题 | 需要下一个角色决策或确认的事 |
| 下一步 | 建议的下一角色与动作 |

## 角色卡

| 角色 | 一句话职责 | 何时使用 |
| --- | --- | --- |
| [planner.md](planner.md) | 把想法变成可验收的规格与任务分解 | 立项阶段 |
| [builder.md](builder.md) | 按规格小步实现并自证 | 执行阶段 |
| [reviewer.md](reviewer.md) | 用验收条件独立复核 | 验收阶段 |

## 使用方式

- 以角色卡内容作为系统提示或任务开场。
- 角色卡只写「职责、输入、输出、边界」，不写具体项目内容。
- 需要新角色时先问：现有三个角色能否覆盖？能，就不新增。
